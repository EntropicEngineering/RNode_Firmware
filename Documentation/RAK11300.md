# RNode on the RAK11300 (RP2040 + SX1262)

This branch adds `PLATFORM_RP2040` / `MCU_RP2040` and the
`BOARD_RAK11300` (0x52) board: the RAKwireless RAK11300 WisDuo module,
an RP2040 with an SX1262 hardwired to the SPI1 peripheral. Built with
the [arduino-pico](https://github.com/earlephilhower/arduino-pico) core,
which supports the module as a first-class variant.

Verified on hardware: rnodeconf provisioning, signature and firmware-hash
validation, Reticulum's `RNodeInterface`, bidirectional traffic against
stock RNode peers (LilyGO T-Deck, RAK4631), and a 25-minute soak at one
packet per 3 s with zero losses.

## Building

```
make prep-rp2040          # installs the rp2040 core and the Crypto library
make firmware-rak11300
```

Firmware lands in `build/rp2040.rp2040.rakwireless_rak11300/RNode_Firmware.ino.uf2`.

## Flashing

Any of the standard RP2040 methods:

- BOOTSEL mode (hold BOOT at power-on) exposes the UF2 drive; copy the
  file or use `picotool load -v -x <uf2>`.
- While RNode is already running, `arduino-cli upload -p <port> --fqbn
  rp2040:rp2040:rakwireless_rak11300` uses the 1200-baud touch.

## Provisioning

The board is provisioned with the RAK4631 product/model bytes — same
SX1262, same band capabilities and TX power, so stock host tooling needs
no changes. The board byte (0x52) distinguishes the hardware.

```
rnodeconf <port> -r --product 10 --model 12 --hwrev <n>   # 779–928 MHz
rnodeconf <port> -L                                       # read firmware hash
rnodeconf <port> -H <hash>                                # store it
```

**After every reflash, refresh the stored firmware hash** (`-L` then
`-H`), or firmware validation keeps the radio offline.

## Platform notes

- **DIO1 is attached level-triggered, not edge-triggered.** The SX1262
  holds DIO1 high until its IRQ flags are cleared, and SPI transactions
  run with the DIO1 GPIO interrupt masked (`SPI.usingInterrupt`). An
  edge that lands inside a masked window would otherwise be lost with
  the line stuck high — permanently ending packet delivery. Delivery is
  additionally gated on the RX_DONE flag so a spurious level trigger
  cannot re-deliver a stale packet.
- **Radio health sentinel** (1 Hz, driven from `loop()`): an online
  radio found in neither RX nor TX is re-armed and, if the condition
  persists, fully reinitialised; carrier-detect latched longer than 30 s
  clears the modem IRQ flags and re-arms receive. It deliberately does
  not live in `check_modem_status()`, whose timed body starves while a
  backed-up TX queue polls `medium_free()` every loop pass.
- **Hardware watchdog** (8 s), fed from `loop()`.
- **EEPROM** uses arduino-pico's flash-backed emulation. Writes land in
  the RAM shadow immediately and are committed after a 250 ms quiet
  period (and always before a reset). Committing per byte would stall
  USB for a flash-sector erase per byte and drop host data during
  EEPROM bootstrap.
- **Modem packet queue** is static and preallocated: this platform has
  no FreeRTOS, and allocating from interrupt context is not safe here.
- **Firmware hash** is soft SHA-256 (Crypto library) over the flash
  binary (`XIP_BASE` to `__flash_binary_end`); the device hash is bound
  to the RP2040's unique flash id.
- **No Bluetooth** on this platform; the host interface is USB CDC.
- Radio SPI runs at 8 MHz (the SX1262's 16 MHz limit leaves no margin).
- Building with `-DRNODE_RP2040_TELEMETRY` emits a 1 Hz diagnostic
  frame (KISS command 0x7D: chip mode, IRQ flags, carrier/queue state)
  for soak-test investigation. Off by default.
